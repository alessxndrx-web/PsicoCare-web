## 2. Cambios implementados

### Neural Awakening
- Construida exclusivamente con el SVG oficial (`public/brand/logo-light.svg`); la geometría se extrae de ese archivo a `components/intro/logo-geometry.ts`. Colores: medianoche `#000022`, celeste `#D9EDF6`, pervinca `#A2AAE8`, morado `#804BDD`.
- Línea de tiempo CSS de 1800 ms: impulso central (0–300), trazado de los cuatro trazos del isotipo con nodos que se activan al paso del impulso (240–860), isotipo oficial completo desde ~920 ms, letras oficiales del logotipo (780–1330) y eslogan «El futuro del bienestar emocional.», vuelo del logo hasta el logo real de la barra de navegación (1350–1800) mientras el fondo se disuelve en el hero, que tiene el mismo color.
- Solo anima `transform`, `opacity` y `stroke-dashoffset`; sin vídeo, canvas, audio ni dependencias nuevas.
- Un script en línea de ~500 bytes decide antes del primer pintado. No se reproduce sin JavaScript, con movimiento reducido, Save-Data, `deviceMemory < 2`, enlaces a secciones (`/#contacto`), recargas ni navegación interna. Se omite con cualquier tecla, clic, rueda o el botón «Omitir introducción». Si la hidratación falla, la animación CSS termina sola.
- El contenido de la portada está en el HTML desde el primer byte; el hero solo se desplaza (sin opacidad) para no retrasar el LCP.

**Validez frente a elegibilidad:** el marcado es Schema.org válido, pero:
- *SoftwareApplication/MobileApplication*: Google exige `aggregateRating` o `review` para el resultado enriquecido; no hay valoraciones reales, así que **no es elegible** (y no deben inventarse).
- *FAQPage*: desde 2023 Google solo muestra este resultado enriquecido para sitios gubernamentales o de salud de autoridad reconocida; **no es esperable** para Psico Care. Se mantiene porque estructura respuestas útiles para buscadores con IA.
- *Organization* (logo) y *BreadcrumbList*: elegibles; dependen de la decisión de Google.
- Validación pendiente con la [Prueba de resultados enriquecidos](https://search.google.com/test/rich-results) y el [validador de Schema.org](https://validator.schema.org/) **tras desplegar** (necesitan una URL pública o el HTML).

## 6. Analítica y verificación — pasos que requieren al responsable

Estado: Vercel Web Analytics ya existe y solo se carga con consentimiento. No hay GA4 (no se añade: Vercel Analytics cubre la necesidad con menos datos personales). No hay verificación de Search Console ni Bing.

1. **Google Search Console**: añadir propiedad de prefijo de URL `https://psico-care-web.vercel.app/`, elegir «Etiqueta HTML», copiar solo el valor de `content` en la variable de entorno de Vercel `GOOGLE_SITE_VERIFICATION` (Production), redesplegar y pulsar «Verificar». Enviar `https://psico-care-web.vercel.app/sitemap.xml`. (Un dominio `*.vercel.app` no admite verificación por DNS; con un dominio propio, usar la propiedad de dominio por DNS.)
2. **Bing Webmaster Tools**: importar desde Search Console o usar la metaetiqueta en `BING_SITE_VERIFICATION`; enviar el mismo sitemap. Bing alimenta Copilot y parte de los buscadores con IA.
3. **Core Web Vitals de campo**: activar Vercel Speed Insights requiere añadir `@vercel/speed-insights`, condicionarlo al mismo consentimiento y **actualizar /privacidad y /cookies** antes; no se hizo para no cambiar el aviso legal sin revisión. Alternativa sin código: informe CrUX en Search Console cuando haya tráfico suficiente.
4. **Eventos de conversión**: los eventos personalizados de Vercel Analytics requieren un plan de pago. Candidatos (sin datos sensibles): clic en descarga del APK, envío del formulario de contacto (sin contenido), inicio de la encuesta. Nunca enviar conversaciones, emociones, respuestas ni texto libre.
